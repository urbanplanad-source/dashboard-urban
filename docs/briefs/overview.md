# 거래처 브리프 운영 요약

## 목적

거래처 브리프 위키는 콘텐츠 초안 작성자가 매번 같은 설명을 다시 묻지 않도록 만드는 장기 기억 저장소다. 대시보드의 `ClientBriefs`는 짧은 운영 입력, 이 위키는 긴 맥락과 원본 자료 연결을 담당한다.

## 현재 기준

- 의료/시술 콘텐츠는 브리프만으로 발행 판단을 하지 않는다.
- `docs/compliance/medical-ad-review-guide.md`와 `docs/compliance/medical-ad-checklist.json`을 함께 읽고, 검수 결과를 `PASS`, `REVISE`, `HOLD` 중 하나로 남긴다.
- 가격, 이벤트, 후기, 전후사진, 수상/인증, 전문성 표현은 근거가 없으면 `자료 확인 필요`로 둔다.
- 대시보드 글 보관함에 저장할 때 memo에 검수 결론과 확인 필요 항목을 짧게 남긴다.

## 좋은 브리프의 조건

좋은 브리프는 아래 질문에 짧고 구체적으로 답해야 한다.

- 이 병원이 어떤 환자에게 어떤 기준으로 선택되어야 하는가?
- 원장님이 선호하는 설명 방식과 피하는 표현은 무엇인가?
- 대표 시술은 어떤 문제를 다루며, 어떤 한계를 반드시 알려야 하는가?
- 가격은 공개 가능한가, 공개한다면 기간/대상/조건은 무엇인가?
- 콘텐츠에서 반복적으로 써도 되는 CTA는 무엇인가?
- 의료광고상 특히 조심해야 할 소재는 무엇인가?
- 최근 발행 콘텐츠와 다음 소재는 어떻게 이어져야 하는가?

## 관리 방식

- 자주 쓰는 핵심은 대시보드 브리프에 입력한다.
- 길고 바뀌지 않는 배경은 `clients/{clientId}.md`에 둔다.
- 원본성 자료는 `sources/{clientId}/`에 보관한다.
- 수정할 때마다 `log.md`에 날짜, 거래처, 변경 이유를 남긴다.
